桌宠补丁 · 无可用帧时不得占据整块输入区
=====================================================

【这是什么】
一个独立的小补丁，改 2 个文件、+19 行代码、+1 个回归测试。
可以直接 `git apply` 到 v4.2.1，不需要任何其他改动。

补丁文件：~/米粒舊物倉/信件/桌宠补丁-无帧时不占输入区.patch


【修的是什么】
素材缺失 / 尺寸与画布不符 / 解码失败时，会是这么一条链子：

    帧长度校验失败（got ≠ expect）
      → 一帧都不交付
      → _frame_pixmap 恒为 None
      → 而 _sync_mask() 只在「帧交付 / 缩放变更 / Q弹动画 tick」时才被调用
      → 于是这条路一次都不会跑
      → 窗口停留在默认的整块矩形输入区
      → 覆盖范围内的鼠标事件全被吃掉
      → 画面又是透明的
      → 用户看到的是「桌宠凭空消失 + 那片区域点不动」，像是系统坏了

根因不是 mask 算错了，而是 **mask 根本没被应用过**。


【两处改动】
1. showEvent() 末尾补一次 _sync_mask()：窗口一显示就先收掉输入区
2. _sync_mask() 在 _frame_pixmap is None 时提前返回，
   并把输入区退化成一个 1×1 的角落点


【踩到的坑（这条值得单独记）】
**不能交空 mask。**

Qt 把空 QRegion / 空 QBitmap 当作「清除 mask」处理，等于恢复整块矩形。
本机实测（Linux/X11，PySide6 6.11.2）：不设 mask / 空 QBitmap / 空 QRegion
三种情况下，XQueryPointer 的指针命中结果**完全一致**；
换成 setMask(QRegion(0, 0, 1, 1)) 之后，窗口内 5 个采样点全部穿透到下层窗口。

所以「把 mask 清空」这个最直觉的写法恰恰是**反效果**的。


【验证】
- 在干净的 v4.2.1 上 `git apply --check` 通过（无冲突、无 fuzz）
- 打上补丁后：tests/test_window_rendering.py → **39 passed, 1 skipped, 0 failed**
- 回归测试在未打补丁时失败于「空 mask 会被 Qt 当成 clearMask」，
  打上补丁后通过 —— 证明它真的在测东西，不是装饰
- 实机验证：故意让包声明 320×180 而素材是 640×360（必然全丢帧），
  窗口区域内 5 个采样点**全部穿透到下层窗口**；
  恢复正常包后用 20×30 像素网格扫 403 个点，画出**完整的角色轮廓**
  （67 点命中，其余全部穿透）


【为什么说它「长期适用」】
它不是一个特性，而是一条**不变量**：

    「窗口没有可画的内容时，不得占据输入区」

这条不变量跟画布尺寸无关、跟 DLC 无关、跟资源格式无关，
所以无论后面怎么重构（v5 的 Core / content / worker 分层），它都成立。

补丁的价值一半在代码、一半在**回归测试**：
重构时把代码重写掉没关系，把测试留着就能守住这条线。

⚠️ 注意：不要把 `CANVAS_W = 320` 那一类跟着一起提交 ——
那是我们自己的素材选择，不是通用修复。这个补丁里**只有**这一个缺陷的修复。


【Windows 侧待确认】
Windows 分支在这条路径上不 setMask，走的是逐像素命中控制器。
建议确认一下：没有可用帧时，Windows 侧是否也存在同类「整块吃事件」的情况。
（我们只在 Linux/X11 上实测过。）

【附带发现，不是补丁，只是情报】
1. 素材命名有两套约定：打包发行版是 `#U4e09…` 转义名，仓库源码是中文名。
   而 library.py 用 f.stem 直接当动画名、ANIM_FILES / ACTS 的键是中文。
   实测：转义名能对上动画表 0/51，中文名 46/51（动作池 42 里对上 40）。
   → 转义名素材能显示，但随机动作池基本是空的。
   → 同一个角色目录里混放两套，会加载 212 段动画、其中一半每帧报"帧长度异常"。
2. 画布尺寸是模块级常量（CANVAS_W/H）。实测它可以被运行时替换
   （所有读取点都写成 catalog.CANVAS_W 这种模块属性访问），
   但同一进程内只能有一份 —— 多窗并存且两窗角色画布不同时会互相打架。
   如果 v5 要做多角色 / 多窗，这条建议在 Phase 1 就定下来。
