## 一、Top 5 结构性风险

### R1 · God File / God Class（规模失控）

| 文件 | 行数 | 内部最大类 | 类体行数 |
|---|---:|---|---:|
| `pet/agent_link.py` | 5,003 | `AgentLinkManager` | **2,736** |
| `pet/window.py` | 4,648 | `PetWindow` | **4,309**（275 个方法） |
| `pet/app.py` | 3,411 | `AppShell` | 2,244 |

**影响**：`PetWindow` 同时承担绘制、物理、拖拽、碰撞、气泡、字符切换、多实例恢复；任何一处小改动都要在一个 4,300 行的类里定位。测试侧虽然总量很大（164 个文件），但**类内分支的测试可读性**会随类体增长而下降——单文件测试（如 `tests/test_window_rendering.py`，931 行）难以与 275 个方法的内部结构一一对应。
**可选改法**：按"生命周期阶段"拆 mixin 或协作者对象（`Renderer` / `DragPhysics` / `BubblePresenter` / `Placement`），保留 `PetWindow` 作为薄门面转发——外部调用点（`trigger_move` / `show_bubble` 等 6 个公开方法）不必改。

## 二、外挂化重构：目标形态与契约

### 5.1 作者已有的雏形（重要前提）

这个仓库**已经在做剥离**了，只是用的不是插件机制：

```
packaging/pet_entry_no_chat.py          ← no-chat 打包入口
PyInstaller excludes=['pet.chat']       ← 编译期切除
```

代价是**每个调用点都要自己记得守卫**，目前散在 9 个文件、42 处：

```
12  pet/app.py                  8  pet/file_interpret.py     5  pet/config.py
 4  pet/vision.py               4  pet/quick_chat.py         3  pet/balance.py
 3  pet/__main__.py             2  pet/modern_settings_dialog.py   1  pet/proactive.py
（统计口径：grep -rnE 'pet\.chat|from \.chat' pet/*.py | grep -v '^pet/chat/'）
```

守卫写法（`config.py:1080`）：

```python
        try:
            from .chat.models import SecretStore  # 惰性导入，且只实例化一次
        except ModuleNotFoundError as exc:
            if exc.name == "pet.chat" or str(exc.name or "").startswith("pet.chat."):
                return
            raise
```

**判断**：这个写法是对的（守卫点收得比想象中干净），但它**不可扩展**——每加一个可选功能就再散 42 处守卫。下面的方案把"散在各处的守卫"换成"一个清单 + 一个加载器"。

### 2.1 manifest 形态

```json
{
  "id": "ai-chat",
  "name": "AI 对话",
  "version": "1.0.0",
  "api": "pet-feature/1",
  "entry": "feature.py",

  "requires": { "pet": ">=4.2,<5", "python": ">=3.11" },

  "provides": [
    { "point": "menu.item",     "id": "chat.open",     "label": "聊天…",      "order": 20 },
    { "point": "hotkey",        "id": "chat.hotkey",   "accel": "Ctrl+Shift+C" },
    { "point": "settings.page", "id": "chat.settings", "title": "AI 设置",     "order": 30 },
    { "point": "tray.item",     "id": "chat.tray",     "label": "打开聊天" }
  ],

  "consumes": [
    { "point": "service.pet_window", "api": "pet.window/1", "optional": false },
    { "point": "service.settings",   "api": "pet.settings/1" },
    { "point": "service.secrets",    "api": "pet.secrets/1" },
    { "point": "slot.speech_bubble", "optional": true },
    { "point": "slot.event_bus",     "api": "pet.events/1" }
  ],

  "config": { "scope": "feature:ai-chat", "schema": "config.schema.json", "migrate": "migrate.py" },
  "secrets": ["api_key", "vision_api_key"],

  "capabilities": { "network": true, "threads": true, "ui": true, "filesystem": "read" },
  "lifecycle": { "unload": "drain_then_close", "drain_ms": 1500 }
}
```

设计要点：
- **`provides`** 是"我往主链上挂什么"，主链只认 `point` 名，不认 `ai-chat`；
- **`consumes`** 是"我要主链给我什么"，全部走**稳定 API 名**（`pet.window/1` 这种带版本号的字符串），不 import 具体类；
- **`capabilities`** 让主链可以在加载前拒绝（例如"无网络变体"直接跳过），比现在的 try/except 早一步；
- **`lifecycle.drain_ms`** 对应作者已经写好的 `ChatService.shutdown()`（有界等待 1500 ms），把那段经验值搬到清单里。

### 2.2 核心侧加载器（伪代码，约 200 行量级）

```python
# pet/plugin.py —— 主链唯一需要新增的文件
import importlib.util, json
from dataclasses import dataclass
from pathlib import Path

API_MAJOR = 1
POINTS = {"menu.item", "hotkey", "settings.page", "tray.item", "slot.speech_bubble"}

@dataclass
class FeatureContext:            # 交给外挂的**全部**能力，就这一个对象
    host: "FeatureHost"
    manifest: dict
    root: Path
    pet: object                  # 只暴露 §5.5 的稳定方法
    events: object               # 实例级信号总线（取代 ChatService 的类级 list）
    secrets: object
    def config(self, defaults: dict) -> dict: ...
    def log(self) -> "Logger": ...

class FeatureHost:
    def __init__(self, pet_api, event_bus, secrets, features_dir: Path):
        self._loaded, self._failed = [], []
        self._dir = features_dir

    def discover(self):
        """只读清单，不 import 任何外挂代码。"""
        out = []
        for mf in sorted(self._dir.glob("*/manifest.json")):
            man = json.loads(mf.read_text("utf-8"))
            if not self._compatible(man):        # api 版本 / pet 版本 / capabilities
                continue
            unknown = {p["point"] for p in man.get("provides", [])} - POINTS
            if unknown:
                self._failed.append((man["id"], f"未知扩展点 {unknown}")); continue
            out.append((mf.parent, man))
        return out

    def load_all(self, on_error="log"):
        for root, man in self.discover():
            entry = root / man.get("entry", "feature.py")
            try:
                mod = self._import_from_path(man["id"], entry)   # 唯一加载点
                ctx = FeatureContext(self, man, root, self._pet, self._events,
                                     self._secrets)
                mod.register(ctx)          # 契约：外挂只暴露 register(ctx)
                self._loaded.append(man["id"])
            except Exception as exc:       # 外挂坏了不能拖垮桌宠
                self._failed.append((man["id"], repr(exc)))
                if on_error == "raise": raise

    def unload_all(self):                  # 关窗/退出路径
        for fid in reversed(self._loaded):
            fn = self._unloaders.get(fid)
            if fn: fn()                    # 各外挂在此 cancel 线程、flush 会话
        self._loaded.clear()

    # ↓ 主链只调用这些"空槽位"，槽位为空时什么都不做
    def build_menu(self, menu):  for it in sorted(self._menu, key=lambda i: i.order): menu.add(it)
    def settings_pages(self):    return sorted(self._pages, key=lambda p: p.order)
    def hotkeys(self):           return list(self._hotkeys)
    def emit(self, topic, **kw): self._events.emit(topic, **kw)   # 外挂之间也走这里
```

对照现在的写法，**收益点是可量化的**：

| 现在 | 改成外挂后 |
|---|---|
| 核心 9 个文件各写 `try: from .chat… except ModuleNotFoundError` | 核心 0 处，只在 `FeatureHost.discover()` 一处判定 |
| `packaging/pet_entry_no_chat.py` 单独打包入口 | 同一个入口，删掉 `features/ai-chat/` 目录即可 |
| `ChatService._global_finished_listeners` 类级全局 | `FeatureContext.events` 实例级总线 |
| 42 处 `pet.chat` 引用 | ≤ 2 处（一个加载器路径 + 一处 `__main__` 探测） |

### 2.3 外挂侧入口契约

```python
# 外挂入口：唯一契约就是 register(ctx)。不 import 主链任何具体类。
from pet_api import Service            # 只依赖稳定的 API 名字，不依赖 pet.window

def register(ctx):
    cfg  = ctx.config(defaults=DEFAULTS)                 # 自己的配置自己管
    bus  = ctx.events
    svc  = build_chat_service(cfg, secrets=ctx.secrets)  # 原 chat/service.py 平移

    # ① 往主链的"空槽位"上挂 UI
    ctx.host.add_menu_item(id="chat.open", label="聊天…", order=20,
                           handler=lambda: open_chat_window(ctx, svc))
    ctx.host.add_settings_page(title="AI 设置", order=30,
                               build=lambda parent: build_ai_page(parent, cfg))
    ctx.host.add_hotkey(accel="Ctrl+Shift+C", handler="chat.open")

    # ② 自己的事件自己发（不再往类级列表里塞回调）
    svc.finished.connect(lambda rid, text: bus.emit("chat.finished",
                                                    request_id=rid, text=text))

    # ③ 需要桌宠配合时，只调稳定 API（就是作者现在已经有的那 6 个方法）
    bus.on("chat.finished", lambda text: ctx.pet.show_bubble(text, duration_ms=3200))
    bus.on("agent.state",   lambda st: ctx.pet.trigger_move(AGENT_ANIM[st]))

    # ④ 退出：作者写好的有界等待直接接上
    ctx.on_unload(svc.shutdown)
```

**注意第三行**：`feat.py` 不 import `pet.window`、不 import `AppShell`。它拿到的 `ctx.pet` 是主链在加载时注入的**门面对象**，只含 `show_bubble / trigger_move / request_link_anim / request_link_idle / request_switch_character / request_quit` 这 6 个已经存在的公开方法——**所以这层剥离不需要改动 `PetWindow` 一行代码**。

### 2.4 迁移路径（每步可独立验收）

| 步 | 动作 | 验收标准 |
|---|---|---|
| 1 | 抽出 `pet_api` 门面（6 个 window 方法 + 事件总线 + secret store） | 门面单元测试可独立通过 |
| 2 | 落地 `pet/plugin.py` 加载器 + 空 `features/` 目录 | 无外挂时桌宠照常启动（等价于今天的 no-chat 变体） |
| 3 | `pet/chat/*` 平移进 `features/ai-chat/`，改写成 `register(ctx)` | 42 处核心引用 → **≤2 处** |
| 4 | 删掉 `packaging/pet_entry_no_chat.py` 与所有 `except ModuleNotFoundError` 守卫 | `grep -rn "pet\.chat" pet/` 输出为空 |

**兼容性**：老用户配置（`~/.config/dsh-pet-standalone/…`）由 `manifest.config.migrate` 接手；老打包变体 `excludes=['pet.chat']` 的语义天然等价于"不投放 `features/ai-chat/`"。

**风险提醒（诚实说）**：第 3 步会碰 `pet/app.py` 里 12 处引用与 `config.py` 的反向依赖（C6），是全流程唯一需要仔细回归的一步；建议先做 1、2 两步（对现有行为零影响），把 3 留到有充分测试时间的窗口。
