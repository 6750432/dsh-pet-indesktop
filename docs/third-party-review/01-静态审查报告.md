## 3. 两个指定验证项

### 3.1 是否缺乏 RAG —— **是，完全没有**

扫描命令与结果：

```bash
grep -rIn --include="*.py" -iE "embedding|faiss|chromadb|sentence[-_]transformers|向量|检索|retriev|\bRAG\b|vector_store|cosine_sim" pet/
# → 命中 7 行，逐条核对后全部为无关：
#   agent_link.py:3536  中文"检索"（按 agent 查找记录，是 dict 查询）
#   dynamic_island.py / collision.py ×5   "单位向量/法线向量"（物理碰撞）
# → 与 RAG 相关的实现：0 处
```

现有"上下文"机制只有 **滑动窗口截断**：

```python
# pet/chat/prompt.py:23-32
def build_messages(self, settings, character_id, history, user_text, role_prompt=None):
    return [{'role':'system','content':self.effective_system_prompt(...)},
            *({'role':m.role,'content':m.content} for m in self.trim_history(
                history, settings.history_message_limit, settings.history_char_limit)),
            {'role':'user','content':user_text.strip()}]

@staticmethod
def trim_history(history, message_limit, char_limit):
    result=[]; used=0; limit=max(100,char_limit)
    for m in reversed(history):
        if result and (len(result)>=max(1,message_limit) or used+len(m.content)>limit): break
        ...
```

配置默认值：`history_message_limit=40`、`history_char_limit=24000`（`chat/models.py:45`）。
**行为含义**：超出窗口的历史被直接丢弃，没有摘要、没有检索、没有长期记忆。

现存的三种"记忆替代物"：

| 模块 | 存什么 | 上限 |
|---|---|---|
| `chat/session_store.py` | 会话消息 JSON（原子替换 + 后台串行写盘） | 无检索能力 |
| `proactive_memory.py` | 识屏**元数据**（时间戳 / 进程名 / 活动分类），明确不存截图 | 默认 20 条，尾部截断 |
| `persona_phrases.py` / `persona_presets/*.json` | 人设短语池 | 静态 |

**若将来要加 RAG，最小改动点**：在 `PromptBuilder.build_messages()`（`prompt.py:23`）拼装前插入一次 retrieval，把召回片段作为 `system` 或 `user` 前缀注入即可——**不需要动 UI、不需要动 ChatService**。这是整个聊天子系统里设计得最干净的一处。

### 3.2 是否有 API 挂口 —— **有，而且是标准口**

**挂口 1：OpenAI 兼容 Provider（主通道）**

```python
# pet/chat/models.py:31  ProviderConfig 全字段（这就是挂口的全部旋钮）
base_url='https://api.deepseek.com'  chat_path='/v1/chat/completions'
model='deepseek-v4-flash'            api_key / api_key_ref
timeout=60.0  temperature=0.7  max_tokens=2048  verify_ssl=True
vision_model / vision_base_url / vision_api_key(_ref) / vision_same_as_chat
```

配 `providers.py` 的 `OpenAICompatibleProvider.stream()`：SSE 流式、`threading.Event` 取消、1 MB 缓冲上限、端点归一化（`normalize_chat_endpoint` 支持 `/v1`、`/v4` 等前缀，注释里点名智谱路径）。

**挂口 2：Agent 事件桥（只读文件通道）**

`<config.dir>/agent-events/<agent>.jsonl`，byte-offset 增量 tail；支持 DSH / Claude Code / Cursor / OpenCode；状态词表统一为 6 个词。

**挂口 3：Node 侧插件**

`integrations/dsh-pet-bridge/`，`package.json` 依赖为空（源码注释写明这是"零依赖红线"，理由是打包版 `_internal` 里没有 `node_modules`）。

**结论**：AI 对话的"输入端"（谁在说话）与"网络端"（走哪个模型）都已经是可配置、可外接的。**它缺的不是挂口，而是"可插拔的生命周期"**——这正是 §5 要解决的。

## 4. 排雷：Top 5 结构性风险点

### R1 · God File / God Class（规模失控）

| 文件 | 行数 | 内部最大类 | 类体行数 |
|---|---:|---|---:|
| `pet/agent_link.py` | 5,003 | `AgentLinkManager` | **2,736** |
| `pet/window.py` | 4,648 | `PetWindow` | **4,309**（275 个方法） |
| `pet/app.py` | 3,411 | `AppShell` | 2,244 |

**影响**：`PetWindow` 同时承担绘制、物理、拖拽、碰撞、气泡、字符切换、多实例恢复；任何一处小改动都要在一个 4,300 行的类里定位。测试侧虽然总量很大（164 个文件），但**类内分支的测试可读性**会随类体增长而下降——单文件测试（如 `tests/test_window_rendering.py`，931 行）难以与 275 个方法的内部结构一一对应。
**可选改法**：按"生命周期阶段"拆 mixin 或协作者对象（`Renderer` / `DragPhysics` / `BubblePresenter` / `Placement`），保留 `PetWindow` 作为薄门面转发——外部调用点（`trigger_move` / `show_bubble` 等 6 个公开方法）不必改。

## 5. 外挂重构推演：把「AI 对话」剥成 DLC

### 5.1 作者已有的雏形（重要前提）

这个仓库**已经在做剥离**了，只是用的不是插件机制：

```
packaging/pet_entry_no_chat.py          ← no-chat 打包入口
PyInstaller excludes=['pet.chat']       ← 编译期切除
```

代价是**每个调用点都要自己记得守卫**，目前散在 9 个文件、42 处：

```
12  pet/app.py                  8  pet/file_interpret.py     5  pet/config.py
 4  pet/vision.py               4  pet/quick_chat.py         3  pet/balance.py
 3  pet/__main__.py             2  pet/modern_settings_dialog.py   1  pet/proactive.py
（统计口径：grep -rnE 'pet\.chat|from \.chat' pet/*.py | grep -v '^pet/chat/'）
```

守卫写法（`config.py:1080`）：

```python
        try:
            from .chat.models import SecretStore  # 惰性导入，且只实例化一次
        except ModuleNotFoundError as exc:
            if exc.name == "pet.chat" or str(exc.name or "").startswith("pet.chat."):
                return
            raise
```

**判断**：这个写法是对的（守卫点收得比想象中干净），但它**不可扩展**——每加一个可选功能就再散 42 处守卫。下面的方案把"散在各处的守卫"换成"一个清单 + 一个加载器"。

### 5.2 目标形态

核心红线：**核心代码里不再出现字符串 `ai-chat`，也不再出现 `pet.chat`。**

```json
    { "point": "hotkey",        "id": "chat.hotkey",   "accel": "Ctrl+Shift+C" },
    { "point": "settings.page", "id": "chat.settings", "title": "AI 设置",     "order": 30 },
    { "point": "tray.item",     "id": "chat.tray",     "label": "打开聊天" }
  ],

  "consumes": [
    { "point": "service.pet_window", "api": "pet.window/1", "optional": false },
    { "point": "service.settings",   "api": "pet.settings/1" },
    { "point": "service.secrets",    "api": "pet.secrets/1" },
    { "point": "slot.speech_bubble", "optional": true },
    { "point": "slot.event_bus",     "api": "pet.events/1" }
  ],

  "config": { "scope": "feature:ai-chat", "schema": "config.schema.json", "migrate": "migrate.py" },
  "secrets": ["api_key", "vision_api_key"],

  "capabilities": { "network": true, "threads": true, "ui": true, "filesystem": "read" },
  "lifecycle": { "unload": "drain_then_close", "drain_ms": 1500 }
}
```

设计要点：
- **`provides`** 是"我往主链上挂什么"，主链只认 `point` 名，不认 `ai-chat`；
- **`consumes`** 是"我要主链给我什么"，全部走**稳定 API 名**（`pet.window/1` 这种带版本号的字符串），不 import 具体类；
- **`capabilities`** 让主链可以在加载前拒绝（例如"无网络变体"直接跳过），比现在的 try/except 早一步；
- **`lifecycle.drain_ms`** 对应作者已经写好的 `ChatService.shutdown()`（有界等待 1500 ms），把那段经验值搬到清单里。

### 5.4 核心侧加载器（伪代码，约 200 行量级）

```python
# pet/plugin.py —— 主链唯一需要新增的文件
import importlib.util, json
from dataclasses import dataclass
from pathlib import Path

API_MAJOR = 1
POINTS = {"menu.item", "hotkey", "settings.page", "tray.item", "slot.speech_bubble"}

@dataclass
class FeatureContext:            # 交给外挂的**全部**能力，就这一个对象
    host: "FeatureHost"
    manifest: dict
    root: Path
    pet: object                  # 只暴露 §5.5 的稳定方法
    events: object               # 实例级信号总线（取代 ChatService 的类级 list）
    secrets: object
    def config(self, defaults: dict) -> dict: ...
    def log(self) -> "Logger": ...

class FeatureHost:
    def __init__(self, pet_api, event_bus, secrets, features_dir: Path):
        self._loaded, self._failed = [], []
        self._dir = features_dir

    def discover(self):
        """只读清单，不 import 任何外挂代码。"""
        out = []
        for mf in sorted(self._dir.glob("*/manifest.json")):
            man = json.loads(mf.read_text("utf-8"))
            if not self._compatible(man):        # api 版本 / pet 版本 / capabilities
                continue
            unknown = {p["point"] for p in man.get("provides", [])} - POINTS
            if unknown:
                self._failed.append((man["id"], f"未知扩展点 {unknown}")); continue
            out.append((mf.parent, man))
        return out

    def load_all(self, on_error="log"):
        for root, man in self.discover():
            entry = root / man.get("entry", "feature.py")
            try:
                mod = self._import_from_path(man["id"], entry)   # 唯一加载点
                ctx = FeatureContext(self, man, root, self._pet, self._events,
                                     self._secrets)
                mod.register(ctx)          # 契约：外挂只暴露 register(ctx)
                self._loaded.append(man["id"])
            except Exception as exc:       # 外挂坏了不能拖垮桌宠
                self._failed.append((man["id"], repr(exc)))
                if on_error == "raise": raise

    def unload_all(self):                  # 关窗/退出路径
        for fid in reversed(self._loaded):
            fn = self._unloaders.get(fid)
            if fn: fn()                    # 各外挂在此 cancel 线程、flush 会话
        self._loaded.clear()

    # ↓ 主链只调用这些"空槽位"，槽位为空时什么都不做
    def build_menu(self, menu):  for it in sorted(self._menu, key=lambda i: i.order): menu.add(it)
    def settings_pages(self):    return sorted(self._pages, key=lambda p: p.order)
    def hotkeys(self):           return list(self._hotkeys)
    def emit(self, topic, **kw): self._events.emit(topic, **kw)   # 外挂之间也走这里
```

对照现在的写法，**收益点是可量化的**：

| 现在 | 改成外挂后 |
|---|---|
| 核心 9 个文件各写 `try: from .chat… except ModuleNotFoundError` | 核心 0 处，只在 `FeatureHost.discover()` 一处判定 |
| `packaging/pet_entry_no_chat.py` 单独打包入口 | 同一个入口，删掉 `features/ai-chat/` 目录即可 |
| `ChatService._global_finished_listeners` 类级全局 | `FeatureContext.events` 实例级总线 |
| 42 处 `pet.chat` 引用 | ≤ 2 处（一个加载器路径 + 一处 `__main__` 探测） |

```python
    # ③ 需要桌宠配合时，只调稳定 API（就是作者现在已经有的那 6 个方法）
```

**注意第三行**：`feat.py` 不 import `pet.window`、不 import `AppShell`。它拿到的 `ctx.pet` 是主链在加载时注入的**门面对象**，只含 `show_bubble / trigger_move / request_link_anim / request_link_idle / request_switch_character / request_quit` 这 6 个已经存在的公开方法——**所以这层剥离不需要改动 `PetWindow` 一行代码**。

### 5.6 迁移路径（4 步，每步可独立验收）

| 步 | 动作 | 验收标准 |
|---|---|---|

## 7. 追加评估：用「米粒那套调试方法」来改这个桌宠，会不会更好？

**结论先说**：会更好，但要**拆成两半**——**米粒方法管"人设与评测"，外挂/RAG/API 管"工程结构"**，两者不冲突，正好互补。而且只有米粒方法里的**两条**能原样带走，另外两条是本地小模型的局部经验，带过来会走偏。

### 7.1 米粒的五条经验，逐条判迁移

| 米粒经验 | 能否迁移 | 理由 |
|---|---|---|
| 人格卡 **590~600 字最稳，961 字必崩** | ❌ **不能** | 那是 **7B 本地模型**的注意力/上下文边界；桌宠默认接远程 API（`ProviderConfig.model='deepseek-v4-flash'`），指令遵循与长上下文完全另一个量级。照搬字数上限＝自缚手脚 |
| **加「例子」有效** | ✅ **能** | few-shot 对大小模型都有效，而且和 §7.2 的"多说法"天然合拍 |
| **加「规则」有害** | ⚠️ **部分** | 小模型上规则会挤压注意力；大模型能吃规则。但"**例子优先于规则**"这条依然成立 |
| **温度别降** | ⚠️ **需重校** | 小模型降温会崩；大模型降温通常更稳，但角色扮演会变呆。桌宠默认 `temperature=0.7`——**先别动**，跑一轮 A/B 再定 |
| **「一问多说法」变体治** | ✅✅ **最该带走** | 这是**评测方法**，与模型无关。而且作者已经在用了（见下） |

### 7.2 好消息：多说法这个思想，作者已经实现过了

`pet/persona_presets/whale_maid.json`（10,726 字节）就是**"每个事件多条说法"**的短语库：

```json
{ "activity.default": [
    "主人～{name}正在当前会话 {sessionName} 里处理{label}，人家替您盯着{tool}～",
    "哼，会话 {sessionName} 里的{name}正在用{tool}继续干活，已经到第{step}步啦。",
    "{name}还在当前会话 {sessionName} 里处理任务呢，主…" ] }
```

每条 key 下挂一组带变量的句子、随机挑一条说——**这跟"一问多说法"是同构解法**，只是用在 **agent 事件碎碎念**上，没用在 chat 的 system_prompt 上。
⇒ 所以你不是要引入外来范式，而是**把仓库里已有的思想往聊天那一格扩一格**。这在 PR 沟通上也是个好角度：不是"我教你做事"，而是"你这套多说法，聊天侧也能用"。

### 7.3 坏消息：聊天人格卡目前是"半截挂口"

三条证据（均已核对）：

1. `PromptBuilder` 的 root 在三个调用点**都硬编码内置目录** `assets/characters`：
   `chat/widgets.py:809`、`quick_chat.py:78`、`file_interpret.py:240`
2. `catalog.external_character_dirs()`（用户级角色目录，含 `~/.config/dsh-pet-standalone-webm-chat/characters/`）**只喂动画资源**（`catalog.py:204/224`），**不参与人格卡加载**
3. 全仓**没有任何角色带 `chat.system_prompt`**——唯一的 `assets/characters/shenshen/videos/manifest.json` 只有 `body_box` / `head_box`

⇒ **现状**：能用的输入只有**设置里那一个文本框**（`ChatSettings.default_system_prompt`）。
`manifest.json → chat.system_prompt` 这条设计**是悬空的：写了也不读**。

⇒ **想按米粒方式做"每个角色一张人格卡 + 一套例库"，需要补一个约 20 行的小挂口**：
把 `PromptBuilder` 的 root 从"单个内置目录"改成"**内置目录 + external_character_dirs() 的顺序查找**"，并在 preset 里加一个 `examples: []` 数组（当前全仓 `examples` 字段 **0 命中**，确认没有现成槽位）。

**这也回答了"会不会更好"的关键一问**：米粒方法的**评测部分今天就能用**（零代码，改文本框 + 自建变体集），**但"每角色一案"的部分需要一个 20 行的挂口**才谈得上。

### 7.4 「外挂走 RAG」：可行，四条硬约束

| # | 约束 | 说明 |
|---|---|---|
| 1 | **钩点唯一且干净** | `PromptBuilder.build_messages()`（`prompt.py:23`）：外挂在拼 messages 前插入召回片段即可，**主链零改动** |
| 2 | **存储选型** | 建议 `sqlite-vec`（米粒那边用过）：单文件、零外部依赖，和本仓库"原子写盘 + 单文件状态"的风格一致（`session_store.py` 就是这么干的） |
| 3 | **隐私红线（最重要）** | 桌宠有识屏能力（`proactive_memory` 记录进程名/活动分类）。这些数据一旦进 RAG 再发远程 API 就是**出网**。→ **默认本地嵌入 + 默认不索引识屏数据**，要开必须单独开关 + 明确提示 |
| 4 | **低功耗红线** | 作者在 `agent_link.py` 头部第 5 条写明"**功能默认全关、隐藏时全线 pause()**"。索引构建与嵌入推理必须放在 pause 状态或空闲时段，不能常驻抢 CPU——**遵守这条既有原则，比多一个功能更重要** |

**第一个用例建议**：做 **`file_interpret.py` 的文件解读**（拖文件给桌宠 → 已经会建会话、已有 prompt 装配点）——RAG over 用户拖进来的文档，价值最高、最贴合现有功能。
**不建议**先做"给闲聊加长期记忆"：桌宠的交互多是短对话，检索容易变成噪声。

### 7.5 「以后更新功能走 API」：要分清两种意思

- ✅ **推荐**：外挂通过**稳定 API 门面**与主链交互（即 §5.5 的 `consumes: service.pet_window / events / secrets / embedding`）。核心只认带版本的 API 名，**新功能 = 新增一个外挂目录，核心不动**。这跟"以后更新功能走 API"是同一个意思，方向对。
- ⚠️ **不建议**：功能以**"远程下发代码"**的方式更新。三条理由：
  ① 桌宠是本地常驻程序，远程下发代码 = 给供应链开后门；
  ② 作者自己已经立过规矩——`agent_link.py` 头部第 6 条："**写入外部配置/hooks 前必须弹窗征得用户明确同意**"，同一套标准理应对代码也成立；
  ③ 仓库里已有 `pet/updater.py`，把更新做成"**下发清单 + 资源，代码仍走本地发布**"就够用了。

### 7.6 一句话总结

> **米粒方法管"人设与评测"，外挂/RAG/API 管"工程结构"。**
> 能原样带走的只有两条：**「一问多说法」的评测循环** 和 **「例子优先于规则」**；
> **字数上限**与**温度**是 7B 局部经验，别带。
> 落地顺序建议：① 今天就能做——用现有文本框跑米粒式人格卡 + 变体集；
> ② 补 20 行让人格卡可外用（每角色一案）；
> ③ 再上 §5 的外挂化，RAG 放在外挂内部，嵌入默认本地；
> ④ 功能更新走**稳定 API 门面**，不走远程下发代码。
